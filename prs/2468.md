## What it does

The block-staleness watchdog returned early when only the log-subscriber set was empty, so a
state-only chain that answered the heartbeat but had stopped delivering blocks was never
reconnected. It now checks both the log and state subscriber sets (matching `detachIfIdle`
and the drain guard), and `reconnect()` re-attaches the block listener for either kind.

## Review items resolved

- reconnect() re-attaching only for log subscribers -> widened to log-or-state.
- catch-up arm correctly kept log-scoped (a state-only chain owes no range).
- comment corrected to match `detachIfIdle`'s docstring.
- regression tests added that fail against the unfixed code (control reverts documented in the PR thread).
- description corrected from "live" to "latent" after review.
