- Area: event tracker (provider-manager)

## What it does

Wires the trace-call matcher (#2393) into the event tracker so workflows can trigger on
reverted and internal calls. `checkBlockStaleness`, `reconnect()` and the drain guard now
test all three subscriber sets (log, state, trace); the post-reconnect catch-up arms for
log-or-trace (state owes no range). Trace decode helpers were vendored to stop drift, and a
trace refusal becomes a learned per-entry capability instead of an infinite retry.

## The strongest proof: a real internal-call ERC-20 transfer through KeeperHub

The trace matcher exists to catch calls a plain top-level log filter misses. Here an ERC-20
transfer runs as an internal call inside a KeeperHub relayer transaction:

- Transaction (Sepolia, status 0x1): https://sepolia.etherscan.io/tx/0x45494db90e017321e7d18d3ac480dde06f129a04fa73f3681f3eff285df9b1ce
- Verified on-chain: the relayer calldata carries selector `0xa9059cbb` and the DAI address; the DAI contract emitted the `Transfer` event (topic0 `0xddf252ad...b3ef`).
- Live workflow using the feature: `kh workflow get qxsd20ivw39ny9ee3s2il` shows "Trace Trigger Demo - ERC20 Transfer Monitor", triggerType Trace, `traceSelector 0xa9059cbb`, chain 1.

That is exactly the internal-call ERC-20 transfer the trace matcher triggers on.
